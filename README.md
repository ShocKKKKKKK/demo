# Демо-сайты для лидов

Статический сайт для GitHub Pages: одна папка на демо-основу, данные лида — маленький JSON
по случайной ссылке. Публикует его приложение AI Lead Hunter (задача 11 части 3b): содержимое
`demo-site/` (кроме `test/`) заливается в отдельный публичный репозиторий.

## Устройство

```
index.html              заглушка «Демо недоступне» (сюда уводит любой неверный или просроченный адрес)
robots.txt              Disallow: / — плюс noindex на каждой странице
shared/demo.js          загрузчик данных и подстановка
shared/demo.css         лента «Демо для …», место под фото, тизер полной версии
shared/video/hero.mp4   видеофон «Розсекречено» (один файл на все демо, 0,6 МБ)
shared/vendor/          gsap 3.15.0 (+ScrollTrigger, SplitText) и lenis 1.3.25 — локальные копии из npm, без CDN
advokaty-gribovod/      основа «Грибовод»: частный адвокат с фото
advokaty-rozsekrecheno/ основа «Розсекречено»: объединение / бюро / нет фото, видеофон
advokaty-wine/          основа «Editorial Wine»: премиум, адвокат-женщина
reviews/                универсальная основа «Сбор отзывов» (любая ниша): чат, QR-картка А6, вікно оцінки
automation/             универсальная основа «Автоматизация заявок» (любая ниша): проигрыватель из 4 сцен
shared/scene.css        общие стили универсальных основ (первый экран, шаги, телефон, чат, CTA, подвал)
shared/scene.js         инициалы в аватарах (`data-initials`) для универсальных основ
data/<token>.json       данные лида (пишет приложение)
d/<token>.html          короткая страница с превью для мессенджеров (пишет приложение)
.github/workflows/cleanup.yml  ежедневное удаление просроченных демо
test/sample.json        профили для ручной проверки (не публикуется)
```

Адрес демо: `/<основа>/?d=<token>`, token — ровно 10 символов `[a-z0-9]`.
`shared/demo.js` берёт `../data/<token>.json`; нет файла, битый JSON или `expires_at < Date.now()` —
переход на `../index.html`. Данные подставляются только через `textContent` / `setAttribute`,
в `href` пускается только `tel:+цифры`. Форма заявки ничего не отправляет: сабмит гасится,
основа показывает «Так заявка прийде вам у Telegram».

## Данные лида

```json
{
	"token": "k3x9q2ab7c", "base": "advokaty-wine", "expires_at": 1767225600000,
	"name": "Ірина Мельничук", "name_line1": "Ірина", "name_line2": "Мельничук",
	"city": "Львів", "phone": "050 987 65 43", "phone_href": "tel:+380509876543",
	"address": "вул. Городоцька, 15, Львів", "hours": "Пн–Пт 10:00–19:00",
	"rating": 4.9, "reviews": 57,
	"slogan": "…", "lead": "…", "services": ["Сімейне право", "…"]
}
```

Универсальные основы (`reviews`, `automation`) берут только `name`, `city` и три поля ниши:

```json
{ "niche_word": "адвокат", "niche_client": "клієнт", "grateful": "буду вдячна" }
```

`niche_word` — слово ниши для метки «адвокат · Київ» («клініка», «спеціаліст»…);
`niche_client` — «клієнт» / «пацієнт» в именительном падеже (в разметке к нему дописываются окончания:
«клієнт**и**»); `grateful` — «буду вдячна» / «буду вдячний» / «будемо вдячні» (по названию лида).
`slogan`, `lead`, `services` у них пустые. Никаких других фактов о лиде эти страницы не показывают.

`rating`, `reviews`, `address`, `hours` — необязательные: блоки с ними пропадают сами.
Фото Google и тексты отзывов в демо не попадают; на месте фото — «Тут буде ваше фото».

## Метки в разметке

| Метка | Что делает |
|---|---|
| `data-demo="поле"` | текст элемента = значение поля (`name`, `name_line1`, `name_line2`, `city`, `phone`, `address`, `hours`, `rating`, `reviews`, `slogan`, `lead`) |
| `data-demo="phone_href"` | поле `*_href` пишется в атрибут `href` |
| `data-demo-repeat="N"` + `data-demo-sep` | значение повторяется N раз (фоновые надписи) |
| `data-demo-if="поле"` | элемент удаляется, если поля нет или оно пустое |
| `data-demo-list="services"` | первый ребёнок — шаблон, клонируется на каждую услугу; внутри `data-demo-item` (текст) и `data-demo-index` («01») |
| `data-demo-long="блок__элемент"` | модификатор `--long` при названии > 28 символов, `--xlong` при > 40 |
| `<html data-demo-title="…">` | подпись вкладки «<название> — …» вместо «— демо сайту» |

После подстановки на `<html>` появляются класс `demo-ready`, событие `demo:ready`,
промис `window.demoReady` и CSS-переменные `--demo-name-word` (длина самого длинного слова
названия — основы ограничивают по ней кегль первого экрана через `cqi`) и `--demo-ribbon-h`
(высота ленты — шапки сдвигаются на неё).

Рядом с рейтингом всегда подпись `<span translate="no">Google Maps</span>`.

## Как добавить основу

1. Скопировать сайт в `demo-site/<ниша>-<название>/`, исходник не трогать.
2. Оставить 2–3 блока (первый экран, услуги, контакты/форма). Остальные секции, страницы,
   их стили, скрипты и картинки удалить. Убрать все факты исходного клиента: имена, фото людей,
   цифры, кейсы, отзывы, телефоны, адреса.
3. В `<head>`: `noindex, nofollow`, `../shared/demo.css` до стилей основы, `../shared/demo.js` без `defer`.
4. Сверху `.demo-ribbon`, после последнего блока `.demo-teaser` (список настоящих секций основы
   и три размытых превью удалённых секций — `img/teaser-1..3.webp`, 480×360), в подвале
   `footer__dev`.
5. В CSS основы задать переменные `--demo-*` (цвета и шрифты тизера, ленты и места под фото)
   и сдвинуть фиксированную шапку на `var(--demo-ribbon-h, 0px)`.
6. Проверить на `test/sample.json`: `python -m http.server` в `demo-site/`,
   открыть `/<основа>/?test=0..5` на ширинах 1600–360 (4 — клиника/пациент, 5 — специалист).
7. Добавить основу в `demo_bases` приложения.

## Универсальные основы

`reviews/` и `automation/` не привязаны к нише (`demo_bases.niche_id = '*'`, `fit` = `reviews` / `automation`):
в приложении это отдельные кнопки «Демо: сбор отзывов» и «Демо: автоматизация заявок» у любого лида,
публикация тем же путём (`data/<token>.json` + `d/<token>.html`). Текст не генерируется ИИ.

- `reviews/` — QR рисует qrcode-generator 1.4.4 с jsDelivr (если не загрузился — узор-заглушка);
  QR ведёт на эту же страницу к шагу 3 (`#review`). Вікно оцінки — стилизованный макет, без логотипа
  и без копии интерфейса Google.
- `automation/` — сцены переключаются по `data-duration`, поля «печатаются» из `data-type`,
  элементы `.reveal` появляются с задержкой `data-delay`; «Програти ще раз» — с начала.
  Запуск — когда проигрыватель попал в экран. `prefers-reduced-motion` — без анимаций.

Демо обещают только то, что реально сделать бесплатно. Писать клиенту первым в Viber автоматически
нельзя без платного Viber Business, SMS — платные; Telegram-бот может написать человеку, только если тот
сам написал боту или нажал кнопку. Поэтому в «Отзывах» Viber — это «одне натискання» (бот даёт готовое
сообщение, адвокат пересылает), автоматически — email и Telegram для тех, кто пришёл через бота;
в «Автоматизации» ответ клиенту — на сайте и письмом, запись — через онлайн-календарь с письмом-напоминанием.

## Что за этим стоит технически

Всё на бесплатных тарифах, без своего сервера.

- **Telegram-бот** — Telegram Bot API (бот создаётся у @BotFather, токен хранится только в обработчике).
  Заявка уходит в чат владельца методом `sendMessage` с `reply_markup` (кнопки «Передзвонити» / «Записати»).
  Бот отвечает клиенту сам, только если клиент сам начал диалог (`/start` по ссылке `t.me/<бот>?start=...`
  или по QR) — так устроен Telegram, писать первым бот не может.
- **Форма → вебхук.** Форма сайта шлёт `fetch` POST на бесплатный Cloudflare Worker (100 тыс. запросов в сутки)
  или Google Apps Script (`doPost`, «Развернуть как веб-приложение»). Обработчик: проверка полей и honeypot,
  `sendMessage` в Telegram владельца, письмо клиенту (если указал почту) — в Apps Script через `MailApp.sendEmail`
  (≈100 писем в сутки на обычном аккаунте), в Worker — через бесплатный тариф Brevo/Resend. Ответ на сайте
  («Дякуємо! … зв'яжеться завтра до 10:00») показывает сама форма после успешного ответа вебхука.
- **Запись на приём** — Google Calendar «Расписание встреч» (appointment schedule, бесплатно в личном аккаунте)
  или Cal.com (бесплатный тариф): клиент сам выбирает время, событие появляется в календаре владельца,
  письмо-подтверждение и напоминание за день календарь отправляет сам. Уведомление владельцу в Telegram —
  тем же вебхуком (Cal.com умеет webhooks; для Google — Apps Script по триггеру календаря).
- **Ссылка на отзывы** — из Google-профиля компании: «Попросить отзывы» в профиле даёт короткую ссылку
  `g.page/r/.../review`, которая сразу открывает окно отзыва. Её же кладём в QR-картку (печать А6) и в готовое
  сообщение бота. Бот «Попросити відгук» — команда/кнопка, которая возвращает владельцу текст с этой ссылкой
  и кнопку «Переслати» (`switch_inline_query` или обычная пересылка). Напоминание через 3 дня — тот же
  Apps Script по времени (триггер), только письмом или в Telegram, если клиент общается с ботом.

## Очистка

`cleanup.yml` раз в сутки (03:17 UTC) и вручную удаляет `data/<token>.json` с прошедшим
`expires_at` и соответствующие `d/<token>.html`.
Продление при ответе «Интересно» — перепубликация JSON с новым `expires_at` из приложения.

**История репозитория не хранит данные лидов.** Репозиторий публичный, и удалённый файл обычно
остаётся в старых коммитах. Поэтому при любом удалении — просроченных демо этой очисткой или
раньше из приложения («Удалить сейчас», коммит через Contents API) — workflow пересобирает ветку
с нуля одним коммитом (`git checkout --orphan`) и делает force-push. Итог: удалённое демо
исчезает из истории ветки в течение суток (после ближайшего ночного запуска; можно запустить
вручную во вкладке Actions → «Очистка просроченных демо» → Run workflow).

Оговорки:
- если приложение публикует демо в момент сжатия, push отклоняется (`--force-with-lease`)
  и история сжимается следующей ночью — опубликованное не теряется;
- GitHub некоторое время хранит недостижимые коммиты по прямому SHA (кеш, форки). Ссылки на
  них нигде не публикуются, со временем их убирает сборка мусора GitHub; для срочного удаления —
  запрос в поддержку GitHub;
- ветку демо-репозитория нельзя защищать от force-push (Settings → Branches), иначе сжатие не пройдёт.
